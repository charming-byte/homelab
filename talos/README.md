## Generate and inspect

Run from the repository root with the mise tools and `SOPS_AGE_KEY_FILE` available:

```sh
task talos:generate-config
```

This is offline: it decrypts the existing `talsecret.sops.yaml`, renders both node
configs, validates each with `talosctl validate --mode metal --strict`, then writes
`rendered/<hostname>.yaml` and `clusterconfig/talosconfig` with mode 0600. These
outputs contain secrets and are ignored by Git. The old
`clusterconfig/kubernetes-node*.yaml` files are no longer used.

The existing secrets bundle is required and is never regenerated by these tasks.
Keep it and the age key: replacing it would change the cluster identity. topf
decrypts SOPS directly, so no plaintext secrets file or 1Password integration is
needed. Existing `.j2` drafts and `../template/` are not part of the active render
pipeline.

## Apply and upgrade

```sh
# Read-only live comparison; topf returns exit code 2 if changes exist.
task talos:diff

# topf displays the diff and asks before applying.
task talos:apply-node IP=192.168.178.56
task talos:apply-node IP=192.168.178.55

# Upgrade a node to the Talos version and schematic in topf.yaml.
task talos:upgrade-node IP=192.168.178.56

# Kubernetes upgrades remain a talosctl operation.
task talos:upgrade-k8s
```

The IP-based task interface is retained; tasks resolve IPs to exact host filters
because topf's `--nodes-filter` matches hostnames, not IPs. Unknown IPs are rejected.
`task bootstrap:talos` applies to maintenance-mode nodes and bootstraps etcd using
`topf apply --auto-bootstrap`; it is for initial cluster creation, not this migration.
`task talos:reset` is destructive and explicitly limits wiping to STATE and
EPHEMERAL (`--full=false`), rather than topf's full-disk default.

## Images and compatibility

The [schematics](schematics/) are the existing factory definitions, referenced with
topf's `@file` syntax. Their locally computed IDs match the previous installer URLs.
They retain the node-specific extensions and kernel arguments. For a changed
schematic, register it using topf's `--submit-to-factory` flag before installation
or upgrade; the existing schematics are already registered.

Kernel arguments now come from the factory image instead of
`machine.install.extraKernelArgs`; `UnattendedInstallConfig` replaces the old
install section, including its legacy GRUB command-line toggle. Installation
continues to select `/dev/sda` with `wipe: false`.

See the [OpenEBS compatibility exception](patches/README.md#network-and-storage)
before converting the remaining kubelet settings. Cilium, externally managed
CoreDNS, control-plane scheduling, metrics bindings, Talos API access, GPU labels,
kernel modules and sysctls are preserved.

References: [topf migration guide](https://postfinance.github.io/topf/main/migration-from-talhelper/),
[Talos 1.14 release notes](https://github.com/siderolabs/talos/releases/tag/v1.14.0).
